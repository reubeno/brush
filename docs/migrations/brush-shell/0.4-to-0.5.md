# brush-shell 0.4 → 0.5

This is the human walkthrough of the changes in brush-shell 0.5. For the
complete list with detection greps, see the agent-oriented guide that ships
with the crate:
[`brush-shell/skills/migrate-0.4-to-0.5/SKILL.md`](../../../brush-shell/skills/migrate-0.4-to-0.5/SKILL.md).
If you use [Symposium](https://symposium.dev/), `cargo agents sync` installs
that guide into your agent automatically once you depend on brush-shell 0.5.

## What changed, and why

brush-shell 0.5 parses its own command line with
[winnow-args](https://github.com/lu-zero/winnow-args) instead of clap,
matching the builtins in brush-builtins 0.3. The `brush` binary no longer
depends on clap for its parsing.

Most users run `brush` rather than link brush-shell, and see only the
behavior changes below. If you use brush-shell as a library, the types in
`brush_shell::args` and `brush_shell::events` now derive winnow-args traits,
so code that treated them as clap types needs updating.

## Quick summary

- `CommandLineArgs` is a `winnow_args::Args`: use `try_parse_from` (without
  the program name), `HELP`, and `completion_script` where you used clap's
  `try_parse_from`, `command`, and `clap_complete`.
- `CommandLineArgs::help` is gone; `version` is a `bool`.
- `TraceEvent` and `InputBackendType` derive `winnow_args::ValueEnum`, and
  still parse with `str::parse`.

## Step by step

### Parse and inspect the command line

```rust
// Before (0.4)
use clap::Parser;
let args = brush_shell::args::CommandLineArgs::try_parse_from(["brush", "-x"])?;

// After (0.5)
use winnow_args::Args;
let args = brush_shell::args::CommandLineArgs::try_parse_from(["-x"])?;
```

winnow-args takes the arguments without the program name, and its
`winnow_args::Error` implements `std::error::Error`. `try_parse_from` parses
the options only; the `brush` binary additionally takes `-c`'s command string
from the first operand and handles `--` as bash does.

### Generate completion scripts

```rust
// Before (0.4)
clap_complete::generate(shell, &mut CommandLineArgs::command(), "brush", &mut out);

// After (0.5)
let script = CommandLineArgs::completion_script(winnow_args::complete::Shell::Bash);
```

The script calls `brush __complete_word__ ...` for its answers, so it stays
in step with the installed binary instead of embedding a copy of the option
list. bash, zsh, fish, elvish and PowerShell are supported.

### Read `version`

`args.version.is_some()` becomes `args.version`. `--help` is answered while
parsing, so there is no `help` field.

## Behavior changes

- `brush --help` and usage errors are rendered by winnow-args, so their
  layout differs from clap's. `-h` is not a help flag, as in bash.
- `brush --version` prints `brush <version>` on stdout.
- A repeated boolean option (`brush -s -s`) is accepted, as in bash.
- `+o NAME` and `+O NAME` are parsed as options only before the first
  operand, so a script's own `+o` arguments reach it intact.
- Man pages and markdown from `cargo xtask gen docs` are rendered from what
  winnow-args' derives write at compile time; `gen docs builtins` writes a
  page for each builtin, and `--target` describes another target.

## Verifying

Build with `cargo build --all-targets` and run your tests. Tests that compare
`brush --help` output are the ones most likely to need updating.
