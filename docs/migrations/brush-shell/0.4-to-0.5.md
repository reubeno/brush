# brush-shell 0.4 → 0.5

This is the human walkthrough of the changes in brush-shell 0.5. For the
complete list with detection greps, see the agent-oriented guide that ships
with the crate:
[`brush-shell/skills/migrate-0.4-to-0.5/SKILL.md`](../../../brush-shell/skills/migrate-0.4-to-0.5/SKILL.md).
If you use [Symposium](https://symposium.dev/), `cargo agents sync` installs
that guide into your agent automatically once you depend on brush-shell 0.5.

## What changed, and why

brush-shell 0.5 parses its own command line with
[usage-rs](https://usage.jdx.dev) instead of clap, matching the builtins in
brush-builtins 0.3. The `brush` binary no longer depends on clap.

Most users run `brush` rather than link brush-shell, and see only the
behavior changes below. If you use brush-shell as a library, the types in
`brush_shell::args` and `brush_shell::events` now derive usage-rs traits, so
code that treated them as clap types needs updating.

## Quick summary

- `CommandLineArgs` is a `usage::Cli`: use `parse_from_argv`, `spec`, and
  `completion_script` where you used clap's `try_parse_from`, `command`, and
  `clap_complete`.
- `CommandLineArgs::help` and `version` are `bool`.
- `TraceEvent` and `InputBackendType` parse with `str::parse`, not
  `clap::ValueEnum`.

## Step by step

### Parse and inspect the command line

```rust
// Before (0.4)
use clap::Parser;
let args = brush_shell::args::CommandLineArgs::try_parse_from(["brush", "-x"])?;

// After (0.5)
use brush_shell::args::CommandLineArgs;
use std::ffi::OsStr;
let argv = [OsStr::new("brush"), OsStr::new("-x")];
let args = CommandLineArgs::parse_from_argv(&argv).map_err(|err| {
    usage::render_failure(CommandLineArgs::spec(), &argv, &err)
})?;
```

`usage::Error` implements neither `Display` nor `std::error::Error`; render it
with `usage::render_failure` (or `render_failure_plain`) to get a message.

`parse_from_argv` parses the options only. The `brush` binary additionally
takes `-c`'s command string from the first operand and handles `--` as bash
does.

### Generate completion scripts

```rust
// Before (0.4)
clap_complete::generate(shell, &mut CommandLineArgs::command(), "brush", &mut out);

// After (0.5)
let script = CommandLineArgs::completion_script(usage::complete::Shell::Bash);
```

The script calls `brush __complete_word__ ...` for its answers, so it stays
in step with the installed binary instead of embedding a copy of the option
list.

### Read `help` and `version`

Both fields are now `bool`: `args.help == Some(true)` becomes `args.help`.

## Behavior changes

- `brush --help` and usage errors are rendered by usage-rs, so their layout
  differs from clap's.
- A repeated boolean option (`brush -s -s`) is accepted, as in bash.
- Man pages and markdown from `cargo xtask gen` are rendered from the usage
  spec.

## Verifying

Build with `cargo build --all-targets` and run your tests. Tests that compare
`brush --help` output are the ones most likely to need updating.
