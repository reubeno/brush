# brush-builtins 0.2 → 0.3

This is the human walkthrough of the changes in brush-builtins 0.3. For the
complete list with detection greps, see the agent-oriented guide that ships
with the crate:
[`brush-builtins/skills/migrate-0.2-to-0.3/SKILL.md`](../../../brush-builtins/skills/migrate-0.2-to-0.3/SKILL.md).
If you use [Symposium](https://symposium.dev/), `cargo agents sync` installs
that guide into your agent automatically once you depend on brush-builtins 0.3.

## What changed, and why

brush-core 0.6 made builtin argument parsing engine-neutral: a builtin
implements `FromArgs` and `HelpContent`, however it parses. brush-builtins 0.3
uses that freedom to parse every builtin with
[usage-rs](https://usage.jdx.dev) instead of clap, through the new
`brush-builtin-usage` adapter. brush-builtins no longer depends on clap.

For most embedders nothing changes: `default_builtins`, `BuiltinSet`, and
`ShellBuilderExt` keep their signatures. What you may notice is the raised
MSRV, the renamed `+`/`-` flag macro if you used it, and differences in
builtin output where bash compatibility improved or help rendering changed.

## Quick summary

- Raise your `rust-version` to at least 1.91.
- If you used `minus_or_plus_flag_arg!`, switch to
  `usage_minus_or_plus_flag_arg!` and parse the enclosing command with
  usage-rs.
- Re-check tests that compare builtin help text or error messages.

## Step by step

### Raise the MSRV

usage-rs requires rustc 1.91, so brush-builtins does too:

```toml
[package]
rust-version = "1.91"
```

### Replace `minus_or_plus_flag_arg!`

The macro declares a flag pair where `-x` enables and `+x` disables. It now
derives `usage::Args`, and takes the `+` spelling as an explicit argument:

```rust
// Before (0.2)
brush_builtins::minus_or_plus_flag_arg!(ExportFlag, 'x', "Mark for export.");

// After (0.3)
brush_builtins::usage_minus_or_plus_flag_arg!(ExportFlag, 'x', "+x", "Mark for export.");
```

Flatten it with `#[usage(flatten)]` into a `#[derive(usage::Cli)]` command
registered through `brush_builtin_usage::usage_builtin!`. The
`From<Flag> for Option<bool>` conversion is gone; call `flag.to_bool()`.

## Behavior changes

These need no code changes, but scripts or tests may observe them:

- `echo` stops reading options at the first operand, as bash does:
  `echo hi -n` prints `hi -n`.
- `set` rejects unknown options (`set -z`) with status 2 instead of ignoring
  them.
- `unset -f -v` fails with bash's message and status 1.
- `printf` reports usage errors in bash's words, and accepts `--` after
  `-v var`.
- Builtin help and usage errors are rendered by usage-rs, so their layout and
  wording differ from clap's.

## Verifying

Build with `cargo build --all-targets`, then run your tests. Tests that
snapshot builtin help or error output are the ones most likely to need
updating.
