# brush-core 0.5 → 0.6

This is the human walkthrough of the changes most embedders will hit. For the
complete list with detection greps and mechanical replacements, see the
agent-oriented guide that ships with the crate:
[`brush-core/skills/migrate-0.5-to-0.6/SKILL.md`](../../../brush-core/skills/migrate-0.5-to-0.6/SKILL.md).
If you use [Symposium](https://symposium.dev/), `cargo agents sync` installs
that guide into your agent automatically once you depend on brush-core 0.6.

## What changed, and why

brush-core 0.6 removes the argument-parsing engine from its public contract.
In 0.5 every builtin had to be a `clap::Parser`, brush-core depended on clap,
and the shell did some option handling on builtins' behalf. In 0.6:

- A builtin implements two small traits, `FromArgs` (arguments in, typed value
  or error out) and `HelpContent` (synopsis, description, detailed help), plus
  `Command::execute`.
- brush-core depends on no parser. The clap integration moved to a new crate,
  `brush-builtin-utils`, whose `clap_builtin!` macro implements both traits
  from an existing `#[derive(Parser)]`.
- The shell passes arguments through exactly as expanded. Deciding what is an
  option is entirely the builtin's business.

The upshot for most embedders is one added dependency and one added line per
builtin.

## Quick summary

- Add `brush-builtin-utils` (and `clap`, if you only had it through brush-core).
- After each clap-derived builtin struct, add
  `brush_builtin_utils::clap_builtin!(TypeName);`.
- Delete any `fn new`, `fn takes_plus_options`, or `fn get_content` from your
  `impl Command` blocks.
- Replace `simple_builtin` / `decl_builtin` / `raw_arg_builtin` registrations
  with `builtin::<T, _>()`, or use the new `Shell::builder().command::<T>(name)`.
- If you register a bare function, stop skipping `args[0]`: the name is no
  longer passed as an argument.

## Step by step

### 1. Cargo.toml

```toml
brush-core = "0.6"
brush-builtin-utils = "0.1"
clap = { version = "4", features = ["derive"] }
```

### 2. Each clap-derived builtin

Before:

```rust
#[derive(Parser)]
struct GreetCommand { /* ... */ }

impl builtins::Command for GreetCommand {
    type Error = brush_core::Error;
    async fn execute<SE: ShellExtensions>(&self, ctx: ExecutionContext<'_, SE>) -> Result<ExecutionResult, Self::Error> { /* ... */ }
}
```

After:

```rust
#[derive(Parser)]
struct GreetCommand { /* ... */ }

brush_builtin_utils::clap_builtin!(GreetCommand);

impl builtins::Command for GreetCommand {
    type Error = brush_core::Error;
    async fn execute<SE: ShellExtensions>(&self, ctx: ExecutionContext<'_, SE>) -> Result<ExecutionResult, Self::Error> { /* ... */ }
}
```

If the old impl overrode `new` to keep `--` and the words after it (the
`try_parse_known` pattern), use `clap_builtin!(GreetCommand, trailing_args =
args)` instead, naming the `Vec<String>` field the override extended. If it
implemented `DeclarationCommand`, use `clap_builtin!(GreetCommand,
declarations = declarations)` and delete that impl. If it overrode
`takes_plus_options`, just delete the override; `+x` options are inferred from
the derive.

Getting the macro's options wrong is a compile error that names the accepted
forms.

### 3. Builtins that ignore their arguments

`SimpleCommand` is gone. A builtin that ignores its arguments and has fixed
help text needs no parser at all:

```rust
struct TrueCommand {}

brush_builtin_utils::verbatim_builtin!(
    TrueCommand,
    synopsis = "true",
    description = "success",
    help = "Returns a successful exit status.\n",
);

impl builtins::Command for TrueCommand {
    type Error = brush_core::Error;
    async fn execute<SE: ShellExtensions>(&self, _ctx: ExecutionContext<'_, SE>) -> Result<ExecutionResult, Self::Error> {
        Ok(ExecutionResult::success())
    }
}
```

The same macro with `args = field` stores every argument untouched, which is
what `raw_arg_builtin` used to do.

### 4. Registration

All four registration functions became one:

```rust
// Before
m.insert("true".into(), simple_builtin::<TrueCommand, SE>());
m.insert("export".into(), decl_builtin::<ExportCommand, SE>().special());

// After
m.insert("true".into(), builtin::<TrueCommand, _>());
m.insert("export".into(), builtin::<ExportCommand, _>().special());
```

Whether a builtin takes declarations is now a property of the type
(`FromArgs::TAKES_DECLARATIONS`, set by the macro's `declarations` and `args`
forms), so it can no longer disagree with the registration.

For a single builtin on a shell builder there is a shorthand:

```rust
let shell = brush_core::Shell::builder()
    .command::<GreetCommand>("greet")
    .build()
    .await?;
```

### 5. Bare-function builtins: the silent change

If you build a `Registration` from a plain function rather than a `Command`
type, two things changed. The struct's fields are private, so construct it with
`Registration::new::<H>(f)`, where `H` implements `HelpContent` (a unit struct
is fine). And the function no longer receives the builtin's own name as
`args[0]`. This one compiles unchanged and silently drops your first real
argument, so check every such function for `skip(1)`, `args[0]`, or
`split_first()` and delete the skip. The invoked name is
`context.command_name`.

### 6. Help text

`ContentType` and `get_content` are gone. Providers implement `HelpContent`:
`synopsis` and `description` return the unframed text (`cd [-L|-P] [dir]`, not
`cd: cd [-L|-P] [dir]`); `help -s` and `help -d` add the framing. `detailed_help`
has a default composed from the two, so most hand-written builtins need only
two one-liners. Consumers read a registration's help through
`synopsis(name)`, `description(name)`, and `detailed_help(name, &options)`.

### 7. Completion enums

`CompleteAction` and `CompleteOption` no longer derive `clap::ValueEnum`. They
implement `Display`, `FromStr`, and `strum::VariantNames` with the names
`complete -A` and `-o` use. See the agent guide, entry 9, for the clap
`value_parser` replacement.

## Behaviour changes to be aware of

- Declaration builtins (`declare`, `local`, `readonly`, `export`, `typeset`)
  stop reading options at the first operand, as bash does.
- `export` now rejects operands that are not valid identifiers, with status 1.
- `help -s a b c` prints one framed line per builtin.

## Verifying

Build with `--all-targets`, then grep your sources for the removed names
(the agent guide's VERIFY section has the exact pattern). Run a bare-function
builtin with one argument and confirm the argument arrives.
